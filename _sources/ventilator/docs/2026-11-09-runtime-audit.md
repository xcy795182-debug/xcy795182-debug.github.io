# 运行底层逻辑再审计

## 方法
对设置入口、下一口生效状态、压力与流量计算、容量积分、呼吸环、容量反馈、监测窗口逐层检查。新增tests/audit-regressions.test.ts，对VC的Vt/Tflow、PC压力/时间/阻力、PSV的PS/ETS、VG/PRVC/VSV容量反馈、FiO2与机械量分离等进行控制变量检查。仅验证程序和教学模型内部因果关系，不据此声称完成临床医学有效性验证。

## 复现并修正的问题
1. SIMV-PC关闭VG且同一批修改指定dp时，自动压力恢复逻辑会覆盖用户dp。回归示例原设置dp=8却得到11.2383；现在只有未指定dp才沿用最后自动值。
2. 直接切换模式会截断当前呼吸，但finish(false)仍执行容量反馈。原复现VG中autoDp由12误增为14。现只有完整、正确分支的呼吸参与反馈，并排除后备及自主无支持分支。
3. 呼气末PEEPi用旧endPeep减去新settings.peep，在PEEP由5调10时旧估计0.1308立即变0。现将每次呼气末状态和当时的设置PEEP一起保存，避免混用时点。
4. 频率原先按下一口开始时结算的呼吸数统计，和实际启动时点错位，且SIMV无PS的自主分支也被计为机器送气。现按已启动的实际送气事件计数，排除无支持自主分支。
5. 分钟通气量原先把完整呼吸Vte一次性加入结算窗口，当前已呼出的气体要等下一口才计入。现直接积分设备端实时呼出流量，维护真实60秒滚动窗口；有独立逐积分步参考测试，不依赖同一份呼吸结算列表。
6. 后备中点击返回PSV/VSV原来只切换backup布尔量，可能在一口气中混用后备和自主压力。现在先截断并结束该呼吸、标记不完整，再等待自主触发；后备数据不能误参与VSV反馈。
7. 被截断的Vte不再覆盖上一完整呼吸Vte；PIP明确标为本口峰压，Vte明确标为上一完整呼吸，以避免跨呼吸读数被误认为同一口测量。

## 已验证的主要关系
- VC同Tflow、同轮廓增大Vt：流量与容量增加，未限压时压力相应变化；延长Tflow：流量降低，Vt保持。
- VC增R或减C：未限压时给定流量和目标Vt保持，而压力改变；达到限压后容量允许不足并显示限制。
- PC增dp或延长Ti：充盈及容量相应变化；增R会降低早期流量并影响容量。压力上升时间改变早期流量。
- PSV增PS：容量及流量增加；提高ETS百分比：吸气时间与容量下降。
- VG/PRVC/VSV：提高容量目标后，通过完整呼吸反馈提高后续压力及流量，非瞬间改写历史。
- FiO2变化不改变三条机械曲线，只改变独立气体交换模型。
- 肺端与设备端环各自容量与各自流量积分一致，相关测试继续通过。

## 验证与限度
共131项测试通过，生产构建通过。此轮22项新增用例包含先复现失败再修正的回归检查，以及独立流量积分/启动事件计数参考。既有长时间运行、极端参数、模式权限、环方向、漏气守恒等检查继续通过。

本模型依然是线性单室、简化触发与容量反馈，不能复刻各品牌控制器，缺乏非线性复张、区域异质性与真实阀门动力学。气体交换仍为简化近似；软件检查结果不能替代独立专业审阅。当前证据不能承诺不存在其他错误，应持续以具体场景、预期关系和复现步骤审阅。
